# コンボ戦略の仕様 — 盤面形状・ゴミ耐性・現実的上限・レース計算

**目的**: 「コンボを繋げ」を実装可能な仕様にする。**理論値ではなく、実測に裏打ちされた到達目標**を出す。
**前提**: `docs/s2-spec.md` §6.3(combo 乗数)/ §6.8(攻撃計算)、`docs/s2-attack-ceiling.md`(実測の分解)
**日付**: 2026-11-16

---

## 0. 最初に: 前提の訂正

**S2 の single(1 ライン、spin なし)の base は 0**。

```
BASE_ATTACK[spin=none] = [0, 0, 1, 2, 4]     # lines = 0,1,2,3,4
                          ↑ single は 0
```

したがって**素の single の攻撃は combo の ln 項だけ**:

| combo | 攻撃 |
|---|---|
| 0–1 | **0** |
| 2–5 | 1 |
| 6–15 | 2 |
| 16+ | 3 |

**これが本仕様の出発点**。長い single コンボは**ほぼ無価値**で、combo 乗数が効くのは **base が大きい消去**(TSD 4 / quad 4 / TST 6)だけ。

## 1. コンボを持続できる盤面形状

### 1.1 構造的な制約(最初に潰しておく)

**コンボが切れる条件**: `lines == 0` の設置(combo が 0 に戻る)。

**したがってコンボ持続 = 毎回 1 ライン以上消すこと。**

**セル保存則**: ピースは 4 セル、1 ラインは 10 セル。**長期的に消せるラインは「置いたセル + 受けたゴミのセル」/10**。ゴミを受けないなら **0.4 ライン/ピースが上限**。

**この 2 つを同時に満たすには「盤面に既に積まれたセルを使う」しかない**。つまり:

> **コンボは「積んだ山からの引き出し」である。** 山を積む区間は 0 ライン・0 攻撃なので、**コンボ区間の攻撃/piece を、山を積む区間のコストで割り引く必要がある**。

**これが「理論値 1.95」が達成不可能な理由**。1.95 は**コンボ区間だけ**の数字で、山を積む区間を含んでいない。

### 1.2 形状ごとの定量比較

「毎回 1 ライン消す」には、**その行の欠損セル数とピースの形が一致**しなければならない。

| 行の欠損 | その行を完成させられるピース | 備考 |
|---|---|---|
| 4 セル | **水平 I のみ** | 4 セルを 1 行に置けるのは I だけ |
| 3 セル | T / L / J(4 セル目は上の行) | |
| 2 セル | O / S / Z(残り 2 セルは上の行) | |
| 1 セル | すべて | |

**形状の評価**:

| 形状 | 1 ライン/ピースを維持できるか | 必要高さ | ゴミ耐性 | 判定 |
|---|---|---|---|---|
| **4-wide ウェル**(6 列を固める) | **×**。4-wide の 1 行は 4 セル。**水平 I だけ**が 1 行を完成させる。O/T/L/J/S/Z は 3+1 か 2+2 で 0 ライン | ウェル深さ + 6 列の高さ(同程度) | **弱い**。ゴミは 1 行追加なのでウェルが 1 行埋まり、**欠損が 4→3 に変わり I が使えなくなる** | **不採用** |
| **1-wide ウェル**(9 列を固める) | **×**。1 行 = 1 セル。**縦 I が 4 行を一気に完成**させる(4 ライン/ピース)。これは「1 ライン/ピース」ではない | 9 列を 20 行近く積む = **50 ピース以上** | **最弱**。ゴミ 1 行でウェルが埋まる | **不採用** |
| **平らな盤面で single を繋ぐ** | **×**。平らな盤面では 1 ピースで 1 行を完成させられない(4 セル < 10 セル)。**積んでから消す**ので 0 ラインの設置が挟まる | 低い | 中 | **不採用** |
| **「欠損 3 セルの段」を作る**(T/L/J で毎回 1 行) | **○(条件付き)**。行の欠損を 3 に保ち、T/L/J を順に置く。**7 種のうち 3 種**しか使えないので、他の 4 種で欠損を 3 に戻す必要がある | 低い(2〜4 行) | **中**。ゴミ 1 行で段が崩れる | **有力** |
| **TSD 主体 + 短いコンボ** | **○**。T-spin double(base 4)を combo 0–4 で撃つ。**コンボは従属** | 低い(TSD は 2 行 + 屋根) | **強い**(TSD は 2 行消すのでゴミを吸収) | **最有力** |

### 1.3 結論: 「長いコンボ」ではなく「combo 2–4 + 高い base」

**実測がこれを支持している**(406 ゲーム、全設置):

| combo | 設置数 | attack/piece | lines/piece |
|---|---|---|---|
| **0** | 173,756 | **0.695** | 0.565 |
| **1–2** | 68,753 | **1.073** | 0.873 |
| **3–4** | 16,509 | **1.196** | 0.878 |
| **5–9** | 6,835 | **1.084** | **0.670** |
| **10+** | 82 | 1.110 | **0.488** |

**combo 3–4 がピーク。combo 5 以上は改善しない。**

理由: combo 5 以上では **lines/piece が 0.670 に落ちる**(= single で繋いでいる)。single の base は 0 なので、combo を伸ばしても ln 項(1〜2)しか増えない。**「コンボを伸ばす」より「combo 2–4 を保ちながら高い base を撃つ」方が攻撃が出る。**

## 2. ゴミ耐性

### 2.1 S2 のゴミの性質(ルール)

| 性質 | 値 | 意味 |
|---|---|---|
| 遅延 | 20 frame | 到着してから出現まで 1 ピース分の猶予がある |
| 上限 | 8 行 | 1 回に出現するのは最大 8 行 |
| 相殺 | イベント順・1 行ずつ | 送信が受信キューを消す |
| Opener phase | 14 ピース | `pending >= sent` なら相殺量 ×2 |
| 穴 | 1 セル/行、縦に揃う | **穴の列が固定** |

### 2.2 コンボとゴミの相互作用

| 状況 | 判断 | 理由 |
|---|---|---|
| **コンボ中にゴミが来た(出現前)** | **コンボを続ける**。ただし**次の 1 手で相殺できるなら相殺する** | 出現前なら盤面は変わらない。相殺すれば盤面が汚れない |
| **コンボ中にゴミが出現した** | **コンボを切ってでもゴミを消す** | ゴミ 1 行でウェル/段が崩れる。崩れたままコンボを続けると 0 ライン設置が挟まって combo が 0 に戻る。**「切る」方が損失が小さい** |
| **コンボ中に 4 行以上のゴミが出現** | **コンボを捨てて立て直す** | 盤面が 4 行上がる。コンボ継続は不可能 |
| **コンボが 5 以上に伸びた** | **伸ばすより、次の消去で高い base を狙う** | §1.3 の実測。combo 5+ は attack/piece が上がらない |

### 2.3 復帰手順(ゴミでコンボが切れた後)

1. **ゴミの穴の列を確認**する(穴は縦に揃う)
2. **穴を埋めない**。穴の列を避けて積む
3. **2 行以上を一気に消せる形**(TSD / quad / double)を作る。single で繋ごうとしない(base 0 で無意味)
4. **B2B を切らない**。ゴミを消すときは spin か 4 行消しにする(GSB +1 も乗る)

## 3. 現実的な上限

### 3.1 上限を決める 3 つの制約

| 制約 | 内容 |
|---|---|
| **セル保存則** | ゴミを受けないなら **0.4 ライン/ピース**が上限 |
| **combo 持続コスト** | コンボ区間の前に「山を積む区間」(0 攻撃)が必要 |
| **single の base = 0** | 長い single コンボは ln 項しか増えない(最大 3) |

### 3.2 到達目標

| 目標 | attack/piece | 根拠 |
|---|---|---|
| **現状** | **0.878** | 実測(406 ゲーム) |
| **最低ライン(受け入れ)** | **1.10** | combo 1–2 の実測 1.073。**「combo 0 を減らす」だけで届く** |
| **目標** | **1.20** | combo 3–4 の実測 1.196。**「combo 2–4 + 高い base」で届く** |
| **上限(理論)** | **1.4〜1.5** | TSD 主体(1.25)に combo 2–4 の乗数(×1.5〜2.0)と B2B +1 を乗せた値。**ただし TSD を毎回は撃てない** |
| **1.95** | **達成不可能** | コンボ区間だけの数字。山を積む区間を含んでいない |

**受け入れ基準は 1.10、目標は 1.20。** 1.5 を超える主張は、実測の裏付けが無い限りしない。

### 3.3 なぜ 1.2 で足りるか(レース計算へ)

CC2 / clys の実測 attack/piece は **0.75〜0.99**。**1.2 なら 1.2〜1.6 倍の優位**。これで 50-0 になるかは §4 で計算する。

## 4. 対戦相手のコンボ耐性とレース計算

### 4.1 実測(CC2 10 ゲーム + clys 10 ゲーム)

| | 勝った 9 ゲーム | 負けた 11 ゲーム |
|---|---|---|
| 我々の attack/piece | 0.829 | 0.780 |
| 相手の attack/piece | 0.747 | **0.989** |
| 我々の被ゴミ | 34.7 | **67.4** |
| 相手の被ゴミ | 43.4 | 37.2 |
| 平均 turn 数 | 124 | 152 |

**負けるゲームの構造**: 相手の attack/piece が **0.989**(勝つゲームでは 0.747)。**相手が攻撃モードに入ると我々の 1.27 倍のレートで打ってくる**。そして我々の被ゴミは **1.8 倍**(67.4 対 37.2)。

**つまり勝敗は「相手の攻撃レートが上がったときに耐えられるか」で決まっている。** 攻撃量の総量ではなく、**burst 耐性**の問題。

### 4.2 50-0 は可能か

**必要な条件**: 50 ゲームすべてで、**相手より先に相手を殺す**。

| ゲーム長 | 我々の攻撃 | 相手の攻撃 | 差 |
|---|---|---|---|
| 124 turn(勝ちの平均) | 0.829 × 124 = **103** | 0.747 × 124 = **93** | +10 |
| 152 turn(負けの平均) | 0.780 × 152 = **119** | 0.989 × 152 = **150** | **−31** |

**現状は「相手が攻撃モードに入ると負ける」。** 1.2 attack/piece にすると:

| ゲーム長 | 我々(1.2) | 相手(0.99) | 差 |
|---|---|---|---|
| 152 turn | **182** | 150 | **+32** |

**逆転する。** ただし:

- **50-0 には「1 ゲームも落とさない」必要がある**。1.2 で平均的に勝てても、**分散**で負けるゲームが出る
- 負けゲームの相手 attack/piece 0.989 は**平均**。最大値はもっと高い(1.5 超のゲームがあり得る)
- **burst 耐性**(受けたゴミを即座に処理する能力)が別途必要。攻撃レートだけでは 50-0 にならない

**結論: 1.2 attack/piece で「勝ち越し」は現実的。50-0 には (a) 1.2 超のレート、(b) burst 耐性、(c) 相手の攻撃が集中する局面での防御、の 3 つが要る。**

### 4.3 相手はコンボを見ていない

CC2 / clys / attax はいずれも S2 非対応で、**コンボを評価していない**。したがって:

- **彼らは「平らに積む」**。穴を残さず、高さを抑える
- **コンボで攻撃を 1.4 倍にすると、彼らの受けるゴミが 1.4 倍になる**
- 彼らのスタックは平らなので、**ゴミ 1 行で死なない**。**20 行近くまで積まないと死なない**
- したがって **「1 ゲームあたりの総攻撃量」が勝敗を決める**。攻撃レートの改善がそのまま勝率に効く

**相手がコンボ耐性を持たないことは、我々の有利ではなく「レースが長引く」ことを意味する。** 1 ゲーム 120〜150 turn かかるので、**攻撃レートの差が累積する**。1.2 対 0.99 の差は 150 turn で 32 行。**これが 20 行のスタックを超えるかが勝敗**。

## 5. 実装への要求(受け入れ基準)

| # | 要求 | 受け入れ |
|---|---|---|
| 1 | **評価関数に `combo` 項**(combo 2–4 を維持する方向) | `combo` 分布で **combo 0 が 53.8% → 40% 以下** |
| 2 | **`combo_potential` 項**(「この設置で 1 行消せるか」) | combo 1–4 の設置割合が増える |
| 3 | **高い base の消去を優先**(TSD / quad) | `spin_attack` の寄与が 31.2% → 35% 以上 |
| 4 | **`attack/piece` を指標に入れる** | **1.10 以上**(最低)、**1.20 以上**(目標) |
| 5 | **burst 耐性**(ゴミ出現後の復帰) | 負けゲームの被ゴミ 67.4 → 50 以下 |

**「combo を 15 まで伸ばす」は要求しない。** 実測が支持しない(§1.3)。

---

## 6. 限界

- **形状の比較は解析的**で、実測ではない。実測は「combo 帯ごとの attack/piece」だけ
- **CC2 / clys の 20 ゲーム**は少ない。attack/piece の推定誤差は大きい
- **レース計算は平均値**で、分散を見ていない。50-0 の判断には分散が必要
- **`lines/piece` 0.667 は 0.4 を超える**。これは**受けたゴミを消している**ため(セル保存則はゴミを含めると成立する)
