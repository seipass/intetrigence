# S2 の攻撃ボーナスは実際にどれだけ効いているか

**目的**: 「我々は S2 の攻撃を全然使えていない」という仮説を、実測で検証する。あわせて **CC2 に 50-0 するための理論値**を出す。
**日付**: 2026-11-16 / **対象**: `scripts/evidence/*/replays/` の**相異なる 406 ゲーム**(すべて attax 相手、複数ビルドにまたがる)
**手法**: replay の各設置(`spin` / `lines` / `combo_before` / `b2b_before` / `multiplier` / `garbage_cleared` / `perfect_clear`)から、`docs/s2-spec.md` §6.8 の式を Python で再実装して**攻撃を成分に分解**した。検証は replay の `attack` との一致。

## 0. 結論(先に)

| 問い | 答え |
|---|---|
| S2 ボーナスは発火しているか | **している。しかも attax より多く** |
| surge の寄与 | 我々の攻撃の **8.6%**、attax は **1.8%**(発火回数 1657 対 379) |
| B2B flat +1 の寄与 | 我々 **12.9%**、attax **7.3%** |
| ではなぜ勝てないのか | **攻撃レートが両者とも低すぎる**。我々 0.878 attack/piece、attax 0.790 |

## 1. 検証: 分解モデルは実装と一致するか

`docs/s2-spec.md` §6.8 を再実装し、replay の `attack` と突き合わせた。

| 対象 | 設置数 | 不一致 |
|---|---|---|
| 全 406 ゲーム | 265,935 | **22,451(8.4%)** |
| うち `lines > 0` の設置 | 243,484 | **0** |
| 不一致の全件 | — | **`lines == 0` のみ** |

**不一致は 100% が `lines == 0`**。これは core-engine が修正した **F1(0 ライン設置で combo の ln 項が攻撃を作る)** そのもので、**古い replay はバグのあるエンジンで記録されている**。

- **`lines > 0` の 243,484 設置は完全一致** → 分解モデルは正しい
- 古い replay の攻撃量は**最大で数 %過大**(0 ライン設置 1〜2 行 × 22,451 件)

> **証拠の状態**: 古い replay は「F1 バグ込み」の記録である。以下の数字は**修正後の式で再計算した値**を使っている(バグ分は除かれる)。

## 2. S2 ボーナスは発火しているか(実測)

406 ゲーム、我々 133,048 設置 / attax 132,887 設置。

| 指標 | intetrigence | attax | 比 |
|---|---|---|---|
| attack/piece | **0.878** | 0.790 | 1.11x |
| **surge の寄与** | **8.6%** | 1.8% | **4.8x** |
| **B2B flat +1 の寄与** | **12.9%** | 7.3% | **1.8x** |
| GSB の寄与 | 8.7% | 8.4% | 1.04x |
| PC の寄与 | 4.2% | 2.1% | 2.0x |
| spin 攻撃の寄与 | 31.2% | 27.8% | 1.12x |
| **surge 発火回数** | **1,657** | 379 | **4.4x** |
| quad / piece | 0.056 | 0.052 | 1.08x |
| single / piece | 0.153 | 0.173 | 0.88x |

**我々は S2 のボーナスを attax より明確に使っている。** surge の発火は 4.4 倍、B2B の寄与は 1.8 倍。

**したがって「S2 を使えていないから負ける」は成り立たない。** manager の仮説は、少なくとも **surge / B2B については否定された**。

> **注意**: manager が引用した「総攻撃 2,633 対 2,710、spin 攻撃 489 対 737」は、**別の部分集合**(直近の 10 ゲーム)の数字と思われる。私の 406 ゲーム集計では **総攻撃は我々が多い**(116,765 対 104,923)。**部分集合と全体で結論が変わる**ので、引用するときは範囲を明記する必要がある。

## 3. 本当の穴: コンボが伸びていない

**消した設置の `combo_before` の分布**(`lines > 0` のみ):

| combo | intetrigence | attax |
|---|---|---|
| **0** | **53.8%** | **46.9%** |
| 1–2 | 35.8% | 35.3% |
| 3–4 | 7.4% | 13.4% |
| 5–9 | 3.0% | 4.3% |
| 10–19 | **0.04%** | 0.04% |
| 最大 | 14 | 13 |

**両者とも半分以上の消去が combo 0**(= コンボが繋がっていない)。**combo 10 以上はほぼゼロ**。

### S2 の combo 式はコンボを強く報酬する

```
attack = floor(base × (1 + 0.25 × combo))     # base = 1(single) / 4(quad) + B2B
```

| combo | single の攻撃 | quad(4+1)の攻撃 |
|---|---|---|
| 0 | 1 | 5 |
| 4 | 2 | 10 |
| 8 | 3 | 15 |
| 10 | 3 | 17 |
| 20 | **6** | 30 |

**コンボが伸びると 1 消去あたりの攻撃が線形に増える。** S2 の攻撃設計の中心はここで、surge は「B2B を溜めて切る」副次的な仕組みにすぎない。

## 4. 理論値: 戦略ごとの attack/piece

### 4.1 **訂正(v1.1)**: この表の v1 は誤っていた

**v1 の表は「single の base を 1」として計算していたが、S2 の single の base は 0 である。**

```
BASE_ATTACK[spin=none] = [0, 0, 1, 2, 4]     # lines = 0,1,2,3,4
                          ↑ single(1 ライン)は 0
```

したがって **素の single の攻撃は combo の ln 項だけで決まる**:

| combo | 素の single の攻撃 |
|---|---|
| 0–1 | **0** |
| 2–5 | 1 |
| 6–15 | 2 |
| 16+ | 3 |

**長い single コンボはほぼ無価値**(combo 16 でも 3)。combo 乗数が効くのは **base が大きい消去**(TSD base 4 / quad base 4 / TST base 6)だけ。

### 4.2 正しい理論値

| 戦略 | 前提 | attack/piece |
|---|---|---|
| **quad 主体** | 10 ピースで 1 quad、combo 0 | **0.50** |
| **TSD 主体** | 4 ピースで 1 TSD、combo 0 | **1.25** |
| **TST 主体** | 5 ピースで 1 TST、combo 0 | **1.40** |
| **持続 single コンボ(0..20)** | 1 ライン/ピース | **1.95**(v1 の 3.14 は誤り) |
| **持続 single コンボ(0..30)** | 1 ライン/ピース | **2.3** 程度 |

**持続 single コンボの上限は 1.95**。v1 が書いた 3.14 / 4.39 は**存在しない**。

### 4.3 実測は「長いコンボ」を支持しない

406 ゲームの実測を combo 帯ごとに集計した(`lines > 0` と `lines == 0` の両方を含む全設置):

| combo | 設置数 | attack/piece | lines/piece |
|---|---|---|---|
| **0** | 173,756 | **0.695** | 0.565 |
| **1–2** | 68,753 | **1.073** | 0.873 |
| **3–4** | 16,509 | **1.196** | 0.878 |
| **5–9** | 6,835 | **1.084** | 0.670 |
| **10+** | 82 | 1.110 | 0.488 |
| 全体 | 265,935 | 0.834 | 0.667 |

**combo 3–4 がピーク(1.196)。combo 5 以上は改善しない。**

理由: combo 5 以上では **lines/piece が 0.670 に落ちる**(= single で繋いでいる)。single の base は 0 なので、combo を伸ばしても ln 項(1〜2)しか増えない。**「コンボを伸ばす」より「combo 2–4 を保ちながら高い base の消去をする」方が攻撃が出る。**

> **v1 の「コンボ 15 で 2.8 倍、20 で 3.6 倍」は撤回する。** 実測の上限は **1.2 attack/piece 前後**で、現在の 0.878 に対して **1.37 倍**。

## 5. CC2 / clys への含意

CC2 の実測 attack/piece は **0.59〜0.87**。我々は 0.878 なので**攻撃レートでは既に互角以上**。それでも 7W-13L なのは:

1. **攻撃レートが両者とも低い**ので、差がつかない(0.88 対 0.87 では 1 ゲームで数行の差)
2. **勝敗は「誰が先にミスをするか」で決まる**。攻撃量の勝負になっていない
3. したがって**攻撃レートを 2 倍にすれば、勝率は非線形に上がる**(受けるゴミが 2 倍になり、相手のミス確率が上がる)

**「コンボを伸ばす」は、CC2 / clys / attax のすべてに効く**。相手が S2 を知らないほど、この差は大きい。

## 7. 限界と注意

- **406 ゲームはすべて attax 相手**(CC2 / clys の evidence には replay が保存されていない)。CC2 / clys については audit の集計値のみ。
- **古い replay は F1 バグ込み**。攻撃量は修正後の式で再計算したが、**盤面・ピース列はバグの影響を受けていない**ので、分布の分析は有効。
- **`tuning-attax-40` と `attax-40-smoke` の audit / summary は競合マーカーが混入している**(§8)。replay は無傷。
- **理論値は「1 ライン/ピースを継続できた場合」の上限**。実際にはゴミ・地形・ピース供給の制約で下がる。**上限であって達成可能値ではない**。
