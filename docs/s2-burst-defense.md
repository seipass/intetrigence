# burst 耐性の仕様 — ゴミ出現のタイミング・危険の定量定義・降ろす手順

**目的**: 「burst を受けたときに何をすべきか」を実装可能な形にする。評価関数の danger 項の**しきい値**を与える。
**根拠**: `docs/s2-spec.md` §7(ゴミシステム)、`crates/core/src/garbage.rs` / `game.rs`、`docs/s2-combo-strategy.md`
**日付**: 2026-11-16

---

## 0. 結論(先に)

| 問い | 答え |
|---|---|
| ゴミはいつ出るか | **送信から 2 turn 後**(frame 12/turn、遅延 20 frame)。**2 turn の猶予がある** |
| 1 回で最大何行か | **8 行**(`GARBAGE_CAP`) |
| 出現の条件 | **0 ライン設置のときだけ**(`take_insertable` は `lines_cleared > 0` なら空を返す) |
| 死ぬ条件 | 出現後の高さが **21 以上**(spawn の最下段セルが row 21) |
| **最重要** | **1 ラインでも消せば、その turn はゴミが出ない。** コンボ維持がそのまま burst 防御になる |
| danger 項のしきい値 | **`H + pending_garbage >= 21` で守備に切り替え**。18〜20 は警告 |

## 1. ゴミ出現のタイミングと量

### 1.1 遅延は 2 turn

```
arrival_frame = 送信した turn の frame = 12 × T
出現条件: arrival_frame + 20 <= current_frame
12T + 20 <= 12t  →  t >= T + 1.67  →  t = T + 2
```

| turn | frame | 出現するか |
|---|---|---|
| T(送信) | 12T | しない |
| T+1 | 12T+12 | **しない**(12 < 20) |
| **T+2** | 12T+24 | **出現し得る**(24 >= 20) |

**猶予は 2 turn**。turn T と T+1 の間に、相殺するか、盤面を整えるか、消せる形を作る。

### 1.2 1 回の上限は 8 行

`GARBAGE_CAP = 8`。**20 行の burst でも 1 回では 8 行しか出ない**。残りは次の 0 ライン設置で出る。

**これは重要**: burst は「一撃で死ぬ」のではなく、**0 ライン設置のたびに 8 行ずつ刻まれる**。**合間に 1 ラインでも消せば止まる**。

### 1.3 出現するのは「0 ライン設置のときだけ」

```rust
pub fn take_insertable(&mut self, lines_cleared: u8, current_frame: u64) -> Vec<u8> {
    if lines_cleared > 0 { return Vec::new(); }   // ← これが burst 防御の本体
    ...
}
```

**1 ラインでも消せば、その turn はゴミが出ない。** これは S2 のルール(combo blocking)。

**したがって「コンボを持続する」ことと「burst を防ぐ」ことは同じ操作**。コンボが切れた瞬間が危険。

## 2. 死ぬ条件(正確に)

### 2.1 spawn は row 21

`PieceKind::spawn_position` の最下段セル:

| ピース | box 原点 y | 最下段セル row |
|---|---|---|
| I | 19 | **21** |
| O | 21 | **21** |
| その他 | 20 | **21** |

盤面は 40 行、可視は 20 行。**row 21 は可視領域の 1 行上**。

**block-out = row 21(または 22)が埋まっている**。つまり **スタック高さ H ≥ 21 で死ぬ**。

### 2.2 ゴミ出現は即死し得る

`Game::insert_garbage` は挿入後に active を再スポーンし、置けなければ**その場で `topped_out`** にする。

**つまり「0 ライン設置 → ゴミ 8 行 → 再スポーン失敗 → 即死」があり得る。**

### 2.3 生存条件

```
出現後の高さ = H + G   (H = 現在の最大高さ、G = その turn に出現する行数)
生存:  H + G <= 20
死亡:  H + G >= 21
```

## 3. 危険の定量定義

### 3.1 3 段階

| 段階 | 条件 | 意味 | 取るべき行動 |
|---|---|---|---|
| **安全** | `H + pending <= 17` | 最大 8 行が出ても `H+8 <= 25`… ではなく、**次の 0 ライン設置で出る量を考えても余裕** | 攻撃を優先してよい |
| **警告** | `18 <= H + pending <= 20` | 出現すると `H+G` が 21 に届き得る | **0 ライン設置を避ける**(必ず 1 行以上消す) |
| **危険** | `H + pending >= 21` | **今 0 ラインを置いたら死ぬ**(G >= 21-H) | **1 ライン消去を最優先**。消せないなら相殺 |

**しきい値の根拠**: `H + G >= 21` で block-out。`G` は最大 8 なので、`H >= 13` でも 8 行で 21 に届く。**`H + pending` で見るのが正しい**(`H` だけでは足りない)。

### 3.2 必要な消去行数

| `H + pending` | 0 ライン設置で出現する行数 | 死ぬか | 必要な消去 |
|---|---|---|---|
| ≤ 20 | G | 死なない | 0 |
| 21 | 8(上限) | **死ぬ** | **1 行以上**(出現自体を止める) |
| 24 | 8 | 死ぬ | 1 行以上 |
| 29 | 8 | 死ぬ | 1 行以上 |

**`H + pending >= 21` では「1 行でも消す」が唯一の生存条件**。消す行数は 1 でよい(出現を止めるだけで足りる)。

**ただし**: 1 行消しても次の turn また 0 ラインを置けば出る。**`H + pending >= 21` の間は、毎 turn 1 行以上消し続ける必要がある**。

### 3.3 危険の持続時間

`pending` は相殺しない限り減らない。**したがって `H + pending >= 21` は、次のどちらかまで続く**:

- **相殺する**(攻撃を送って pending を消す)
- **ゴミを出し切る**(8 行ずつ出して、`H` が上がる代わりに `pending` が減る)

**「出し切る」は危険**: 8 行出ると `H` が 8 上がる。`H + pending >= 21` で出し切ると、ほぼ確実に死ぬ。

**したがって `H + pending >= 21` では「相殺」が本線**。「1 行消して延命」は相殺が間に合わないときの次善策。

## 4. 降ろす手順

### 4.1 優先順位(上から)

| # | 行動 | 条件 |
|---|---|---|
| **1** | **相殺する**(ゴミを送る) | `pending >= 1`。送れる攻撃がある |
| **2** | **1 行以上消す**(出現を止める) | 相殺が間に合わない。`H + pending >= 21` |
| **3** | **穴を埋める** | ゴミが出た後。穴の列を埋めて盤面を下げる |
| **4** | **複数行消し**(2 行以上) | 盤面を下げる。**single で繋ぐより優先** |
| **5** | **B2B を維持** | 可能なら。ただし生存が最優先 |

### 4.2 「コンボを捨てる」判断

| 状況 | 判断 |
|---|---|
| `H + pending <= 17` | **コンボを維持** |
| `18 <= H + pending <= 20` | **コンボを維持しつつ、0 ライン設置を避ける**(1 行消しで繋ぐ) |
| `H + pending >= 21` | **コンボを捨ててよい**。1 行消しで出現を止める方が優先。**コンボの ln 項(1〜2 行)より、8 行の出現を止める方が価値が高い** |
| ゴミが出現した直後 | **コンボは既に切れている**(0 ライン設置で切れた)。**立て直しに集中** |

### 4.3 穴の扱い

- S2 の穴は **1 セル/行、縦に揃う**(`MESSINESS_WITHIN = 0.0` なので列が変わりにくい)
- **穴の列を埋めない**。埋めるとその列が下がり、他の列が相対的に上がる
- **穴の列を避けて積み、2 行以上を一気に消す**形を作る

## 5. 評価関数への要求(しきい値)

### 5.1 danger 項の形

**現在**: `danger_height = Σ max(0, h_c - 12)²`(固定 12)

**問題**: **`pending_garbage` を見ていない**。ゴミが 8 行来ているときも、来ていないときも同じ。

**要求**: **`H + pending` を引数にする**。

```
effective_height = max_column_height + pending_garbage
danger = Σ_c max(0, h_c + pending - 12)²      # 列ごとに pending を足す
```

または単純に:

```
danger = max(0, (max_height + pending) - 17)²   # 18 以上で効き始める
```

### 5.2 しきい値

| パラメータ | 値 | 根拠 |
|---|---|---|
| `danger_start` | **17** | `H + pending = 18` から警告(出現で 21 に届き得る) |
| `danger_critical` | **21** | この値で「今 0 ラインを置いたら死ぬ」 |
| `pending_weight` | **1.0** | pending 1 行 = 高さ 1 行(同じ重み) |

**`pending_weight = 1.0` が正しい理由**: ゴミ 1 行は高さ 1 行と同じ。**pending は「まだ来ていない高さ」**なので、同じ重みで足す。

### 5.3 守備への切り替え

```
if max_height + pending >= 21:
    # 攻撃より生存。1 行消しを最優先
    attack_weight = 0
    survival_bonus = 大
elif max_height + pending >= 18:
    # 0 ライン設置を避ける。1 行消しに価値
    avoid_zero_line = 大
else:
    # 通常。attack/line を最大化
```

**「攻撃を 0 にする」のは極端**だが、`H + pending >= 21` では**攻撃しても死んだら意味がない**ので妥当。

## 6. 9004-A の崩壊(53 turn、被ゴミ 22、最終 y 18)

**観測**: 53 turn で 22 行受け、最終高さ 18 で死んだ。送信は 9 行だけ。

**解釈**: 序盤に 22 行の burst を受け、**相殺が 9 行しかできず、13 行が盤面に出た**。高さ 18 で死んだのは、**`H + pending >= 21` の状態で 0 ライン設置をした**ため。

**この 1 件が示すこと**:
- **平均レートを上げても、この種の崩壊は防げない**
- 必要は **`H + pending >= 21` で「攻撃を捨てて 1 行消しに切り替える」**
- **50 ゲームで 1/20 の崩壊率 = 期待 2.5 回**。**1 回でも 50-0 は不可能**

**したがって danger 項の `pending` 対応は、平均レートの改善より優先度が高い。**

## 6.1 現行実装との差分(`crates/bot/src/eval.rs`)

**実装済み**(`53896a4`):

```rust
pub const SURVIVAL_PENDING: u32 = 8;
pub const SURVIVAL_HEIGHT: u32 = 15;
pub const DANGER_BASE: i32 = 12;
// danger_height = Σ_c max(0, h_c + incoming - DANGER_BASE)²   ← 和を使っている ✓
// survival 判定 = incoming >= SURVIVAL_PENDING || height >= SURVIVAL_HEIGHT   ← OR ✗
```

| 項目 | 現行 | **仕様** | 判定 |
|---|---|---|---|
| `danger_height` の引数 | `h_c + incoming` | `h_c + pending` | **✓ 正しい** |
| **survival 切り替え** | **`incoming >= 8` または `height >= 15`** | **`height + incoming >= 21`** | **✗ 誤り** |
| `DANGER_BASE` | 12 | 15〜17 | 要調整 |

### なぜ OR が誤りか

| 状態 | 現行の判定 | 実際 | 問題 |
|---|---|---|---|
| `H=15, pending=0` | **守備** | `15+0=15 <= 20` で**安全** | **攻撃を無駄に捨てる** |
| `H=5, pending=8` | **守備** | `5+8=13 <= 20` で**安全** | **攻撃を無駄に捨てる** |
| `H=14, pending=6` | 守備(OR で真) | `14+6=20` で**ぎりぎり生存** | 妥当 |
| **`H=17, pending=3`** | **通常**(17<15? いいえ、17>=15 で守備) | `17+3=20` 生存 | — |
| **`H=13, pending=8`** | **守備**(pending>=8) | `13+8=21` で**死ぬ** | 守備で正しい |

**OR は「どちらかが大きいと守備」なので、片方が小さいときに早すぎる**。**和で見るべき**。

### 修正案

```rust
// 守備に切り替える
let projected = max_height + incoming;
if projected >= 21 {
    // 危険: 今 0 ラインを置いたら死ぬ。攻撃より 1 行消し
} else if projected >= 18 {
    // 警告: 0 ライン設置を避ける
}
```

**`DANGER_BASE` は 15〜17 を推奨**。12 だと `H+pending = 13` から罰則が始まり、**通常のプレイでも常に danger が効いて攻撃項を圧迫する**(これが「安全側に倒れて攻撃しない」の一因だった)。

## 6.2 実測: 負け 2 件は「net damage が −11」(`cc2-projected`、18 勝 2 敗)

`scripts/evidence/cc2-projected/` の 20 ゲームを再集計した。

| | n | turn | sent | recv | **net** | a/p | 最終 y | 相手 y |
|---|---|---|---|---|---|---|---|---|
| **勝ち** | 18 | 59–636(平均 250) | 36–343 | 16–186 | **+16〜+157(平均 +58)** | 0.69–0.89 | 2–10 | 16–25 |
| **負け** | 2 | **60 / 109** | **20 / 37** | **31 / 48** | **−11 / −11** | 0.65 / 0.66 | **21 / 20** | **10 / 7** |

**負け 2 件の特徴**:

1. **net damage が両方 −11**。**送った量が半分以下**(20 / 37 対 勝ちの平均 100 超)
2. **ゲームが短い**(60 / 109 turn 対 勝ちの平均 250)
3. **相手の盤面が低い**(y = 10 / 7)。**相手は余裕で勝っている**。接戦ではない
4. **我々だけが死んでいる**(y = 21 / 20)

**したがって負けの構造は「序盤に攻撃できず、burst を受けて自滅」**。攻撃レースの接戦ではなく、**一方的に押し込まれた**ケース。

### 6.2.1 序盤の防御は Opener Phase の ×2 相殺

S2 の Opener Phase(設置 1〜14 個目)では、`pending >= sent` なら**相殺量が ×2**になる(`docs/s2-spec.md` §7.4)。

**序盤に 1 ラインでも消せば、2 ライン分キャンセルできる。** 逆に言えば、**序盤に消さないと ×2 の恩恵を全部捨てる**。

60 turn で 31 行受けて 20 行しか送れなかった 9007-B は、**Opener Phase で消せていない**可能性が高い(14 ピース中に何ライン消したかは replay で確認できる)。

**要求**: **設置 1〜14 個目で最低 2 ライン消す**。1 ラインにつき 2 行キャンセルなので、2 ラインで 4 行分になる。

### 6.2.2 `attack/line` 1.73 は非現実的だった — 目標を修正

`a/line = s × 2.5 + (1-s) × x`(s = spin ライン比率、x = 非 spin の平均 attack/line)。

**現状**: a/line 1.19、spin clear% 16.1%、平均 lines/clear 1.48 → **s ≈ 21.8%、x ≈ 0.825**。

| s(spin ライン比率) | x=0.825 | x=1.0 | x=1.25(全非 spin が quad 相当) |
|---|---|---|---|
| 22%(現状) | 1.19 | 1.33 | 1.53 |
| 30% | 1.33 | 1.45 | 1.63 |
| 40% | 1.50 | 1.60 | **1.75** |
| 50% | 1.66 | **1.75** | 1.88 |

**a/line 1.73 には「spin ライン比率 40〜50%」が必要**。これは**トップ人間でも到達が難しい水準**で、**重みの調整では届かない**。

**修正した目標**:

| 指標 | 現状 | **現実的な目標** | 備考 |
|---|---|---|---|
| `attack/line` | 1.19 | **1.33〜1.40**(spin 30〜35%) | 1.73 は撤回 |
| `attack/piece` | 0.761 | **0.85〜0.89** | 1.10 は撤回 |
| **`net damage`** | 勝ち +58 / 負け −11 | **全ゲームで >= 0** | **これが本命の指標** |
| **崩壊件数** | 1/20 | **0/50** | 50-0 の必要条件 |

> **`attack/piece` を主指標にしないでください。** 負け 2 件の a/p は 0.650 / 0.661 で、勝ちの平均 0.77 と**大差ない**。**a/p は勝敗を判別していない**。判別しているのは **net damage と最終 y**。

## 6.3 9007-B の replay 診断(実測)

`scripts/evidence/cc2-projected/replays/seed-9007-sheet-B.jsonl`。intetrigence は **seat 2**(CC2 が seat 1 で先に解決)。

### 序盤 40 turn の推移

| turn | IT 消去 | IT 送信 | OPP 消去 | OPP 送信 |
|---|---|---|---|---|
| **0–8** | **0(9 連続)** | 0 | 0 | 0 |
| 9 | 2 | 1 | 0 | 0 |
| 11 | 1 | 0(相殺 1) | 2 | **3** |
| 13 | **0(コンボ切れ)** | 1 | 0 | 0 |
| 14–23 | **0(10 連続)** | 0 | 0 | 0 |
| 29 | 4 | **8** | 0 | 0 |
| 33–34 | 0 | 0 | 4+2 | **3+6 = 9** |
| 40 | 3 | 0 | 4 | 6 |
| **累計(0–40)** | **23 ライン** | **15** | **16 ライン** | **28** |

### 診断

1. **序盤 9 turn 連続で 0 ライン**。攻撃 0 のまま 18 行近く積む。**これが崩壊の起点**
2. **`attack/line` が 0.65**(23 ライン → 15 攻撃)。**CC2 は 1.75**(16 ライン → 28 攻撃)。**我々はライン数で上回りながら攻撃で負けている**
3. **CC2 は一度も相殺していない**(`cancelled = 0`)。我々の攻撃 15 行は**そのまま CC2 の盤面に出て、CC2 に GSB +1 と combo を与えた**
4. **我々は 27 行を受けて 23 ライン消している**。**消去の大半がゴミ処理に使われ、攻撃に変換されていない**

### 含意: 強い相手にゴミを送ると相手が強くなる

CC2 は我々のゴミを消して **GSB +1**(`garbage_cleared > 0` かつ spin/4 行)と **combo** を得る。**送るほど相手の攻撃が増える**。

**したがって「攻撃量を増やす」は、相手が強いほど効きにくい。** 効くのは:

- **`attack/line` を上げる**(同じ消去でより多く送る)
- **相手が消せない形で送る**(8 行 burst を一度に。ただし上限 8)
- **序盤の 0 ライン連続をなくす**(攻撃 0 の区間を作らない)

### 序盤 9 連続 0 ラインは「仕様上もったいない」

Opener Phase(設置 1〜14)の ×2 相殺は、**pending があるときだけ**効く。9007-B では CC2 の初回攻撃が t=11 なので、**t=0〜10 は相殺する相手がいない**。

**それでも「9 連続 0 ライン」は無駄**:
- 攻撃 0 のまま高さが上がる
- **コンボが 0 のまま**(t=13 で切れた後、t=14〜23 も 0)
- **`attack/line` が上がらない**

**要求**: **序盤 14 ピースで最低 3 ライン消す**(t=9 の 1 回だけでなく、t=0〜8 の間にも 1〜2 ライン)。**「最初の 9 ピースは積むだけ」を許さない。**

## 7. 限界

- **しきい値 17/21 は解析値**。実測で検証していない(bot-dev の測定で確認する)
- **`pending` は TBP の state に含まれるか要確認**。含まれない場合、レフェリー側で渡す必要がある
- **「1 行消しで延命」のコスト**を評価していない。1 行消しは攻撃 0〜1 行なので、延命と引き換えに攻撃を失う
- **9004-A の詳細な盤面遷移は見ていない**。replay があれば検証できる
