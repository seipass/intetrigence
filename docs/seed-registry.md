# Seed レジストリ(焼き付き台帳)

**目的**: 使用済みの seed 範囲を一元管理し、**評価 seeds をチューニングに使い回す事故**と**特定 seed 値への最適化**を防ぐ。
**規律**: 範囲は「使ったら二度と戻さない」。評価に使った範囲は**焼き付き**。
**仕様**: [`docs/s2-referee-protocol.md`](s2-referee-protocol.md) §1.5(評価 seeds の事前確定手続き)

---

## 1. 状態の定義

| 状態 | 意味 | チューニングに使えるか |
|---|---|---|
| **未使用** | まだ一度も使っていない | 使える(使ったら状態を更新する) |
| **チューニング** | 重み・パラメータ・評価関数の調整に使った | 引き続き使える(ただし評価には使えない) |
| **評価** | ラウンド用に事前確定した(実行前) | **使えない** |
| **焼き付き** | 公式マッチで使った | **使えない(恒久)** |

**評価 seeds の選び方**: 「未使用」の連番 25 個を選び、`docs/seeds-round-N.md` に列挙してコミットする。同じコミットで本台帳を「評価(ラウンド N)」に更新する。実行後に「焼き付き」へ。

Rust のラウンドは [機械判定用の除外範囲](evaluation-seed-exclusions.txt) と、ほかの追跡済み `docs/seeds-round-*.md` の割当を起動前に照合する。Lab 等で消費した範囲を追加するときは、本台帳と除外範囲を一緒に更新する。

Rust の公式ラウンドと Lab の `--first-to` は、同一端末ユーザーの `evaluation-seeds` ディレクトリに共有の割当を記録する。場所は [計測ロック](../scripts/evidence/README.md#measurement-lock) の隣。Rust はラウンド全体、Lab は各局のシードを開始前に登録する。どちらかに使ったシードは、別 clone の実行でも再割当できない。中断した対戦は元の条件と出力先を指定して `--resume` で再開する。端末をまたぐ共有には追跡済みの台帳を使う。

## 4. 予約・注意

- **20001–20050 は旧 goal の最終マッチ用に予約されたまま**。新 goal のラウンドで使う場合は、本台帳で「解除して評価に使う」と明記する(黙って使わない)。
- 新しい範囲は **30001 以降**を使う(ラウンドごとに 25 個ずつ: 30001–30025、30026–30050、…)。
- **attax 側の使用範囲**(1001–1200 / 2001–2060 / 5001–5050 / 7001–7050)と重ならないこと。重なると「held-out」の主張が崩れる。
- 範囲を追加したら、**必ずこの台帳を同じコミットで更新する**。

## 5. 監査の観点(ラウンド実行前に確認すること)

1. 評価 seeds が**過去のどの範囲とも重なっていない**か(本台帳で確認)
2. `docs/seeds-round-N.md` が**実行コミットより前**にコミットされているか
3. `docs/seeds-round-N.md` に**intetrigence のビルドコミット**が書かれているか
4. 実行後、本台帳が**焼き付き**に更新されているか
5. 評価 seeds が**チューニングのログ・レポートに現れていない**か(`grep` で確認)

### 5.1 attax の視野と `visible_rows`(2026-11-15 確定)

| 対象 | 視野 | 根拠 |

**`visible_rows` はハードコードせず、相手のソースから自動検出する**(ハーネスは `12196ec` で `movegen.ts` の `ROWS` を読む方式に変更)。

### 5.3 探索修正により無効化された重み(2026-11-16)

**M2 / M3 のチューニングで得られた重みは、探索が動いていない前提で校正されていた。** したがって**その重みを「チューニング済み」として扱ってはいけない**。

**何が起きたか**(bot-dev、`00d1a5e`):

- anytime ループが期限超過で反復を捨てて `None` を返し、**全設定で 1-ply greedy** にフォールバックしていた(毎手 ~105ms は消費)
- 修正後は depth 8 / width 324 の探索が動く(**greedy フォールバック 0 回**)
- ところが CC2 相手の勝率は **7W-3L → 3W-7L に低下**
- 原因: `holes=−30` / `height_sq=−12` が `attack=14` を上回り、**攻撃しない方向**に変わった(quad 170→113、single 355→466)

**これは「重みが悪い」のではなく「重みが探索の強さに条件付けられていた」**。探索を変えたら重みを再校正しなければならない。

| 対象 | 扱い |
|---|---|
| M2 / M3 の重み | **無効**。引用するときは「1-ply 前提の重み」と併記 |
| `tuning seeds 9001–9010` | **使用済みのまま**(消費は取り消さない) |
| `9011–9020` | 2026-11-16 の再校正で使用済み。現行の用途は §2 を参照。 |
| 評価 seeds | **未使用。まだ焼かない**(§5.4) |

### 5.4 評価 seeds を焼く条件(2026-11-16)

**次の 3 つが揃うまで評価 seeds を焼かない**:

1. **探索が動いている**(`suggestion` に `depth` / `width` / `nodes` / `fallback` が載り、greedy フォールバック率が記録できる。protocol §8.4.1)
2. **重みが再校正されている**(`attack/piece` が攻撃項の変更に反応する。spec §6.9)
3. **段階 1 の相手(CC2)に tuning seeds で 45/50 以上**。50/50 に届かなくても、**「あと少し」の状態**になってから焼く

理由: 評価 seeds は**使ったら焼き付き**で、再挑戦は**新しい seeds でラウンド全体のやり直し**。探索も重みも定まらない段階で焼くと、**25 個の seeds を捨てる**ことになる。
